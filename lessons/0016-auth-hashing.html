Identity: Password Hashing & Auth

Lesson 0016 · Implementation · Securing the vault

The single idea in this lesson: Never store a password in plain text. If your database is leaked, plain passwords are a catastrophe. We use Hashing (one-way encryption) to store a "fingerprint" of the password instead of the password itself.

1. The Cardinal Sin of Backend

Imagine a user signs up with the password "Password123!". If you save that directly in your SQLite file, any developer or hacker with access to the file can see it.

The Solution: Hashing with Bcrypt.
Hashing is not encryption. Encryption is two-way (encrypt $\rightarrow$ decrypt). Hashing is one-way. You can turn a password into a hash, but you can never turn a hash back into the password.

How Login Works with Hashes:

  1. User provides password "Password123!" during login.
  2. The server hashes that input using the same algorithm.
  3. The server compares the new hash with the stored hash. If they match, the password was correct.

2. Step 1: Installing Bcrypt

Run this in your terminal to install the industry-standard hashing library:

npm i bcrypt && npm i -D @types/bcrypt

3. Step 2: Updating the User Entity

We need a place to store the hash. Edit /src/users/user.entity.ts:


// Add this column to your User class
@Column()
passwordHash: string;

4. Step 3: The AuthService (The Logic)

We don't put login logic in the `UsersService` because authentication is its own domain. We create a new AuthModule.

Run these commands:


nest g mo auth
nest g s auth
nest g co auth

Edit /src/auth/auth.service.ts:


import { Injectable, BadRequestException } from '@nestjs/common';
import * as bcrypt from 'bcrypt';
import { UsersService } from '../users/users.service';

@Injectable()
export class AuthService {
  constructor(private readonly usersService: UsersService) {}

  async signUp(username: string, email: string, pass: string) {
    // 1. Hash the password
    const saltRounds = 10; 
    const hashedPass = await bcrypt.hash(pass, saltRounds);

    // 2. Save user with the hash, NOT the plain password
    return this.usersService.createUser(username, email, hashedPass);
  }

  async login(email: string, pass: string) {
    const user = await this.usersService.findByEmail(email);
    if (!user) throw new BadRequestException('Invalid credentials');

    // 3. Compare provided password with stored hash
    const isMatch = await bcrypt.compare(pass, user.passwordHash);
    if (!isMatch) throw new BadRequestException('Invalid credentials');

    return { message: 'Login successful!' };
  }
}

5. Step 4: Updating the UsersService

The `UsersService` needs a way to find a user by email and a way to save the password hash. Edit /src/users/users.service.ts:


// Update createUser to accept the passwordHash
async createUser(username: string, email: string, passwordHash: string): Promise<User> {
  const newUser: User = {
    id: Math.random().toString(36).substr(2, 9),
    username,
    email,
    passwordHash, // Store the hash!
    createdAt: new Date(),
  };
  return this.usersRepo.create(newUser);
}

// Add this method for the AuthService to use
async findByEmail(email: string): Promise<User | null> {
  // You'll need to add findByEmail to your users.repository.ts first!
  return this.usersRepo.findByEmail(email);
}

6. Step 5: Wiring the Modules

Since `AuthService` uses `UsersService`, we must import `UsersModule` into `AuthModule`. Edit /src/auth/auth.module.ts:


import { Module } from '@nestjs/common';
import { AuthService } from './auth.service';
import { AuthController } from './auth.controller';
import { UsersModule } from '../users/users.module';

@Module({
  imports: [UsersModule], // Give Auth access to Users
  providers: [AuthService],
  controllers: [AuthController],
})
export class AuthModule {}

Important: In /src/users/users.module.ts, make sure to add UsersService to the exports array so other modules can use it!

How to verify your work

  1. Sign Up: Create a POST endpoint in `AuthController` that calls `authService.signUp()`. Save a user.
  2. Check DB: Open db.sqlite (using a SQLite browser). You should see a long, random string of characters in the passwordHash column—not the plain password.
  3. Login: Create a POST endpoint in `AuthController` that calls `authService.login()`.
    • Try the correct password $\rightarrow$ 200 OK.
    • Try a wrong password $\rightarrow$ 400 Bad Request.
Reflect: Notice that the `UsersService` is still just a "Data Manager." It doesn't care about bcrypt or login logic. The `AuthService` is the "Security Guard" that handles the hashing and comparison.
