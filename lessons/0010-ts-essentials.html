TypeScript Essentials for NestJS

Lesson 0010 · Practical · The language of Nest

The single idea in this lesson: NestJS isn't just "written in" TypeScript; it is built on TypeScript's most advanced features. To stop fighting the compiler, you must master three specific concepts: Decorators, Interfaces/Types, and Generics.

1. Decorators: The "Stickers" of Nest

You've seen `@Controller()`, `@Injectable()`, and `@Get()`. In TypeScript, these are called Decorators.

What they actually are: A decorator is just a function that receives a class, method, or property and "stamps" it with metadata. It doesn't usually change the code; it just tells Nest how to treat the code.

Mental Model: Imagine a plain cardboard box. - You slap a sticker on it that says "Fragile". - The box is still a box, but the delivery driver (NestJS) now knows to handle it with care. - The sticker is the Decorator; the driver is the Nest Runtime.

2. Types vs. Interfaces

In NestJS, you will see both type and interface. While they look similar, they have different roles in a backend app.

Interfaces: Used to define the shape of an object or a contract for a class.
Use these for: Repositories, Service contracts, and API responses.


interface IUserService {
  findById(id: string): Promise<User>;
}

Types: Used for unions (this OR that) and aliases.
Use these for: State management, specific ID types, or combined shapes.


type UserStatus = 'active' | 'inactive' | 'suspended';
type Result<T> = { success: boolean; data?: T; error?: string };

Crucial Rule: Remember Type Erasure. Interfaces and Types vanish when TS is compiled to JS. If you need a type to exist at runtime (like for validation), you must use a Class.

3. Generics: The "Variable" for Types

Generics allow you to create a component that works with any type, but still keeps its type safety. You see them as the angle brackets: <T>.

Example: The Generic Response
Instead of creating a UserResponse, CatResponse, and OrderResponse, you create one generic response:


// T is a placeholder for "Whatever type I put here later"
interface ApiResponse<T> {
  data: T;
  timestamp: Date;
}

// Now we use it for different types:
const userResponse: ApiResponse<User> = { data: userObj, timestamp: new Date() };
const catResponse: ApiResponse<Cat> = { data: catObj, timestamp: new Date() };

In Nest, you'll see this most often in Repositories: Repository<User>. This tells the repository: "I am a generic data tool, but specifically for the User entity."

4. Modifier Keywords (The Access Control)

NestJS relies heavily on access modifiers in constructors. This is a TypeScript shortcut that does two things at once.


constructor(private readonly usersService: UsersService) {}

By adding private readonly inside the constructor, TypeScript automatically:

  1. Declares a property named usersService on the class.
  2. Assigns the incoming value to that property.
  3. Ensures it cannot be changed (readonly) and cannot be accessed outside the class (private).
It's shorthand for: this.usersService = usersService;
