The Persistence Layer: TypeORM & SQLite

Lesson 0014 · Implementation · Making data last

The single idea in this lesson: To move from "In-Memory" storage (arrays) to "Persistent" storage (databases). We will use TypeORM as our ORM and SQLite as our database because it's a simple file on your disk—no server installation required.

1. Installing the Database Engine

First, we need the TypeORM core and the SQLite driver. Run these in your terminal:

npm i @nestjs/typeorm typeorm sqlite3
  • @nestjs/typeorm: The bridge between NestJS and TypeORM.
  • typeorm: The ORM that translates TS to SQL.
  • sqlite3: The actual driver that reads/writes the .sqlite file.

2. Configuring the Connection (The Root)

As we learned in the theory lessons, we use forRoot() in the root module to set up the global connection.

Edit /src/app.module.ts:


import { Module } from '@nestjs/common';
import { TypeOrmModule } from '@nestjs/typeorm';
import { UsersModule } from './users/users.module';
import { User } from './users/user.entity';

@Module({
  imports: [
    TypeOrmModule.forRoot({
      type: 'sqlite',
      database: 'db.sqlite', // This will create a file in your project root
      entities: [User],       // Tell TypeORM which entities to manage
      synchronize: true,      // ⚠️ DEV ONLY: auto-creates tables based on entities
    }),
    UsersModule,
  ],
})
export class AppModule {}

3. Turning the Entity into a Table

TypeORM needs special decorators to know how a class maps to a database table. Edit /src/users/user.entity.ts:


import { Entity, PrimaryGeneratedColumn, Column } from 'typeorm';

@Entity() // This tells TypeORM: "This class is a database table"
export class User {
  @PrimaryGeneratedColumn('uuid') // Auto-generate a unique ID (UUID)
  id: string;

  @Column() // Maps to a standard column in the table
  username: string;

  @Column({ unique: true }) // Ensures no two users have the same email
  email: string;

  @Column({ default: () => 'CURRENT_TIMESTAMP' })
  createdAt: Date;
}

4. Updating the Repository (The "Real" Implementation)

Now we replace our array with the actual TypeORM repository. We will use the "Medium" approach: a custom repository that wraps the generic TypeORM one.

Edit /src/users/users.repository.ts:


import { Injectable } from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import { Repository } from 'typeorm';
import { User } from './user.entity';

@Injectable()
export class UsersRepository {
  constructor(
    @InjectRepository(User) 
    private readonly ormRepo: Repository<User>
  ) {}

  async create(user: Partial<User>): Promise<User> {
    const newUser = this.ormRepo.create(user); // Create entity instance
    return this.ormRepo.save(newUser);       // Save to DB
  }

  async findById(id: string): Promise<User | null> {
    return this.ormRepo.findOneBy({ id });
  }

  async findAll(): Promise<User[]> {
    return this.ormRepo.find();
  }
}

5. Final Wiring (The Feature Module)

We need to tell the `UsersModule` that it should provide the `User` entity to the repository.

Edit /src/users/users.module.ts:


import { Module } from '@nestjs/common';
import { TypeOrmModule } from '@nestjs/typeorm';
import { User } from './user.entity';
import { UsersService } from './users.service';
import { UsersController } from './users.controller';
import { UsersRepository } from './users.repository';

@Module({
  imports: [
    TypeOrmModule.forFeature([User]), // Register the entity for this module
  ],
  providers: [UsersService, UsersController, UsersRepository],
})
export class UsersModule {}

How to verify your work

  1. Check the files: Run the app. You should see a new file named db.sqlite appear in your project root.
  2. Persist Data:
    1. Create a user via POST request.
    2. Stop the server (Ctrl+C).
    3. Start the server again (npm run start:dev).
    4. Find the user via GET request. It should still be there!
Architecture Reflection: Notice that the UsersService and UsersController didn't change a single line of code. Because we used the Repository pattern, we swapped the entire storage engine (Array → SQLite) without affecting the business logic. This is the power of decoupling.
