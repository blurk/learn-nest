The Digital Passport: JWT & Guards

Lesson 0017 · Implementation · Stateless Authentication

The single idea in this lesson: HTTP is stateless—the server forgets who you are the millisecond a request ends. To solve this, we use a JWT (JSON Web Token). It is a signed "passport" that the client carries. The server doesn't need to remember the user; it just needs to verify the signature on the passport.

1. How JWT Works (The Mental Model)

Imagine a nightclub with a strict bouncer:

  1. The Login: You show your ID to the manager (AuthService). The manager gives you a VIP Wristband (the JWT).
  2. The Secret: The wristband is signed with a Secret Key that only the manager knows. You cannot forge this wristband.
  3. The Access: Every time you want to enter a room (API Route), you just show the wristband to the bouncer (the Guard).
  4. The Verification: The bouncer doesn't call the manager; he just looks at the signature on the wristband. If it's valid, you're in.

2. Step 1: Installing the JWT Tools

Run these in your terminal:

npm i @nestjs/jwt @nestjs/passport passport passport-jwt && npm i -D @types/passport-jwt

3. Step 2: Configuring the JWT Module

We need to tell Nest how to sign the tokens. Edit /src/auth/auth.module.ts:


import { Module } from '@nestjs/common';
import { JwtModule } from '@nestjs/jwt';
import { PassportModule } from '@nestjs/passport';
import { AuthService } from './auth.service';
import { AuthController } from './auth.controller';
import { UsersModule } from '../users/users.module';

@Module({
  imports: [
    UsersModule,
    PassportModule,
    JwtModule.register({
      secret: 'MY_SUPER_SECRET_KEY', // In real apps, use an environment variable!
      signOptions: { expiresIn: '1h' }, // Token expires in 1 hour
    }),
  ],
  providers: [AuthService],
  controllers: [AuthController],
})
export class AuthModule {}

4. Step 3: Issuing the Token

Update the `login` method in /src/auth/auth.service.ts to return a token instead of a simple message.


import { JwtService } from '@nestjs/jwt';

// ... in the constructor
constructor(
  private readonly usersService: UsersService,
  private readonly jwtService: JwtService // Inject the JWT tool
) {}

async login(email: string, pass: string) {
  const user = await this.usersService.findByEmail(email);
  if (!user) throw new BadRequestException('Invalid credentials');

  const isMatch = await bcrypt.compare(pass, user.passwordHash);
  if (!isMatch) throw new BadRequestException('Invalid credentials');

  // Create the "Passport"
  const payload = { sub: user.id, email: user.email };
  return {
    access_token: await this.jwtService.signAsync(payload),
  };
}

5. Step 4: The Guard (The Bouncer)

Now we create a Guard to protect our routes. Create /src/auth/jwt-auth.guard.ts:


import { Injectable, CanActivate, ExecutionContext, UnauthorizedException } from '@nestjs/common';
import { JwtService } from '@nestjs/jwt';
import { Request } from 'express';

@Injectable()
export class JwtAuthGuard implements CanActivate {
  constructor(private readonly jwtService: JwtService) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const request = context.switchToHttp().getRequest<Request>();
    const token = request.headers.authorization?.split(' ')[1]; // Extract "Bearer TOKEN"

    if (!token) throw new UnauthorizedException('No token provided');

    try {
      const payload = await this.jwtService.verifyAsync(token);
      request['user'] = payload; // Attach user info to the request for use in controllers
      return true;
    } catch {
      throw new UnauthorizedException('Invalid or expired token');
    }
  }
}

6. Step 5: Protecting Routes

Now you can lock any route using the @UseGuards() decorator. Edit /src/users/users.controller.ts:


import { UseGuards } from '@nestjs/common';
import { JwtAuthGuard } from '../auth/jwt-auth.guard';

@Controller('users')
export class UsersController {
  // ...

  @Get('me') // New endpoint to get current logged-in user
  @UseGuards(JwtAuthGuard)
  getMe(@Req() req) {
    return req.user; // Returns the payload we attached in the Guard
  }

  @Delete(':id')
  @UseGuards(JwtAuthGuard) // Only logged-in users can delete!
  async remove(@Param('id') id: string) {
    return this.usersService.deleteUser(id);
  }
}

How to verify your work

  1. Login: POST to /auth/login. Copy the access_token.
  2. Access Protected Route: GET to /users/me.
    • Without Token: Should get 401 Unauthorized.
    • With Token: Add a header Authorization: Bearer YOUR_TOKEN_HERE. You should get your user info!
Reflect: We have achieved Statelessness. The server doesn't store a "session" in memory. This means if you have 10 servers running your app, a user can log in on Server A and then make a request to Server B, and Server B will still know who they are because it can verify the token signature.
