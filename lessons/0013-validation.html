Data Validation and DTOs

Lesson 0013 · Practical · Guarding the gateway

The single idea in this lesson: Never trust the client. A DTO (Data Transfer Object) is a contract that defines exactly what the API expects. Combined with a Validation Pipe, Nest can automatically reject bad requests with a 400 Bad Request before they ever touch your business logic.

1. The "Wild West" Problem

Currently, your controller looks like this:


@Post()
async create(@Body() body: { username: string; email: string }) { ... }

This is "type-hinting," not "validation." If a client sends an empty object {} or a number instead of a string, TypeScript cannot stop it because TypeScript disappears at runtime. Your service will receive undefined and potentially crash or save corrupt data.

2. Step 1: Installing the Guards

Nest uses two powerful libraries for validation. Run these in your project terminal:

npm i class-validator class-transformer
  • class-validator: Allows you to use decorators (like @IsEmail()) to define validation rules.
  • class-transformer: Allows Nest to convert plain JSON objects into actual class instances.

3. Step 2: Creating the DTO

Create a file at /src/users/dto/create-user.dto.ts. We use a Class here, not an interface, because classes exist at runtime.


import { IsEmail, IsNotEmpty, IsString, MinLength } from 'class-validator';

export class CreateUserDto {
  @IsString()
  @IsNotEmpty()
  @MinLength(3, { message: 'Username must be at least 3 characters long' })
  username: string;

  @IsEmail({}, { message: 'Please provide a valid email address' })
  email: string;
}

4. Step 3: Activating the Global Pipe

Defining the DTO isn't enough; we need to tell Nest to actually use the validation rules. We do this in main.ts using the ValidationPipe.

Edit main.ts:


import { NestFactory } from '@nestjs/core';
import { ValidationPipe } from '@nestjs/common'; // 1. Import the pipe
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // 2. Tell Nest to use this pipe globally for every single request
  app.useGlobalPipes(new ValidationPipe({
    whitelist: true,               // Strip away properties that are not in the DTO
    forbidNonWhitelisted: true,    // Throw an error if extra properties are sent
    transform: true,               // Automatically transform payloads to DTO classes
  }));

  await app.listen(3000);
}
bootstrap();

5. Step 4: Updating the Controller

Now, replace the plain object in your controller with the CreateUserDto.

Edit /src/users/users.controller.ts:


import { CreateUserDto } from './dto/create-user.dto'; // Import DTO

@Post()
async create(@Body() createUserDto: CreateUserDto) {
  // Now we can trust that createUserDto.username and .email are valid!
  return this.usersService.createUser(createUserDto.username, createUserDto.email);
}

How to verify your work

Try to break your API using Postman:

  1. Invalid Email: Send { "username": "bob", "email": "not-an-email" }.
    Result: You should get a 400 Bad Request with a message about the email.
  2. Too Short: Send { "username": "bo", "email": "bob@test.com" }.
    Result: You should get a 400 Bad Request about the minimum length.
  3. Extra Data: Send { "username": "bob", "email": "bob@test.com", "admin": true }.
    Result: Because we set forbidNonWhitelisted: true, Nest will reject this because admin is not in the DTO.
Reflect: Notice that the Service and Repository didn't change at all. We added a security layer at the Gateway (the Controller) that protects the rest of the application from bad data.
