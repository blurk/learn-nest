First Project: Workspace Setup

Lesson 0011 · Practical · From theory to code

The single idea in this lesson: Setting up a professional NestJS environment is about more than just running a command. It's about configuring the Tooling (CLI, Node, NPM) so the environment helps you write correct code instead of fighting you.

1. The Tooling Stack

To build with NestJS, we use a specific set of tools. Ensure you have these installed on your machine:

  • Node.js (LTS): The runtime that executes our JavaScript/TypeScript.
  • NPM / PNPM / Yarn: The package manager that downloads our libraries.
  • Nest CLI: The command-line tool that scaffolds our project.

Install the Nest CLI globally:

npm i -g @nestjs/cli

2. Scaffolding the Application

Instead of creating folders by hand, we use the CLI to create a standardized structure that every Nest developer recognizes.

Run the magic command:

nest new my-nest-app

The CLI will ask you which package manager you want to use. Choose npm (or your preferred one).

3. The "First Sight" Anatomy

Once the project is created, open it in VS Code. You will see a /src folder. This is where 99% of your work happens. Here is what you'll find:

  • main.ts: The ignition switch. It calls NestFactory.create() to boot the app.
  • app.module.ts: The Root Module. This is the heart of the app where everything is wired together.
  • app.controller.ts: A basic "Hello World" controller to prove things work.
  • app.service.ts: A basic service that returns the "Hello World" string.

4. Running the App (Development Mode)

In backend development, we don't want to restart the server every time we change a line of code. We use Watch Mode.

Run the app:

npm run start:dev

Now, open your browser to http://localhost:3000. You should see "Hello World!". If you change the string in app.service.ts and save, the browser will update automatically after a quick refresh.

5. The CLI Productivity Shortcuts

Stop creating files manually. The Nest CLI can generate the "Module→ Service→ Controller" trio for you in seconds.

The "Feature" Workflow:

  1. Generate Module: nest g mo users (Creates users.module.ts)
  2. Generate Service: nest g s users (Creates users.service.ts and adds it to the module)
  3. Generate Controller: nest g co users (Creates users.controller.ts and adds it to the module)

Notice how the CLI automatically updates the app.module.ts or users.module.ts for you. It handles the "Registration" step we learned in the theory lessons!
