Building the User Management API

Lesson 0012 · Implementation · The Full Cycle

The goal of this lesson: To build a complete, working feature by following the architectural chain we've studied. We will build a User Management system that allows us to create and find users.

Prerequisite: Please have a fresh NestJS project created using nest new my-nest-app and have the server running with npm run start:dev.

Step 1: Scaffolding the Feature

We start by using the CLI to create the structure. This ensures all registration in the modules is handled for us.

Run these commands in your terminal:


nest g mo users
nest g s users
nest g co users

Check your /src folder. You now have a /users directory with a module, service, and controller. The UsersModule is already registered in app.module.ts.

Step 2: The Entity (The Shape)

We need to define what a "User" looks like. Create a file at /src/users/user.entity.ts.


export class User {
  id: string;
  username: string;
  email: string;
  createdAt: Date;
}

Step 3: The Repository (The Data Access)

To keep our service "clean," we will implement a simple repository. For this lesson, we will use an In-Memory repository (a simple array) so we can focus on the pattern without needing a database installed.

Create /src/users/users.repository.ts:


import { Injectable } from '@nestjs/common';
import { User } from './user.entity';

@Injectable()
export class UsersRepository {
  // Our "Fake" Database
  private users: User[] = [];

  async create(user: User): Promise<User> {
    this.users.push(user);
    return user;
  }

  async findById(id: string): Promise<User | null> {
    return this.users.find(user => user.id === id) || null;
  }

  async findAll(): Promise<User[]> {
    return [...this.users];
  }
}

Crucial: You must register the repository in users.module.ts in the providers array!

Step 4: The Service (The Thinking)

Now we move the business logic into the service. The service will handle ID generation and basic validation.

Edit /src/users/users.service.ts:


import { Injectable, NotFoundException } from '@nestjs/common';
import { UsersRepository } from './users.repository';
import { User } from './user.entity';

@Injectable()
export class UsersService {
  constructor(private readonly usersRepo: UsersRepository) {}

  async createUser(username: string, email: string): Promise<User> {
    // Business Logic: Generate a random ID
    const newUser: User = {
      id: Math.random().toString(36).substr(2, 9),
      username,
      email,
      createdAt: new Date(),
    };

    return this.usersRepo.create(newUser);
  }

  async getUserById(id: string): Promise<User> {
    const user = await this.usersRepo.findById(id);
    
    // Business Logic: Handle "Not Found" state
    if (!user) {
      throw new NotFoundException(`User with ID ${id} not found`);
    }
    
    return user;
  }
}

Step 5: The Controller (The Gateway)

Finally, we expose the service to the world. The controller should be "thin"—just calling the service.

Edit /src/users/users.controller.ts:


import { Controller, Post, Get, Body, Param } from '@nestjs/common';
import { UsersService } from './users.service';
import { User } from './user.entity';

@Controller('users')
export class UsersController {
  constructor(private readonly usersService: UsersService) {}

  @Post()
  async create(@Body() body: { username: string; email: string }) {
    return this.usersService.createUser(body.username, body.email);
  }

  @Get(':id')
  async findOne(@Param('id') id: string): Promise<User> {
    return this.usersService.getUserById(id);
  }
}

How to verify your work

Use a tool like Postman, Insomnia, or the REST Client extension in VS Code.

  1. Create a User: Send a POST request to http://localhost:3000/users with body { "username": "sena", "email": "sena@example.com" }.
    Copy the id from the response.
  2. Find the User: Send a GET request to http://localhost:3000/users/{id}.
  3. Test Error: Send a GET request with a fake ID. You should see a 404 Not Found.
Reflect: Notice the flow. The Controller handles the HTTP request, the Service handles the "User" logic, and the Repository handles the "Array" logic. If we decided to move from an Array to a Database, we would only change the Repository file.
