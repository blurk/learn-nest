The Request-Response Cycle: Controllers and Routing

Lesson 0006 · Practical · First code writes

The single idea in this lesson: a Controller is the "Front Desk" of your application. Its only job is to take an incoming HTTP request, ask a Service for the answer, and return an HTTP response. It does not "think"; it only "routes".

1. The Journey of a Request

Before we write code, let's trace the path of a single request to your server:

  1. The Client (Browser/Postman) sends a request: GET /cats/all.
  2. The Server (Express/Fastify) receives the raw packet and asks Nest: "Who handles /cats/all?"
  3. The Controller matches the route. Nest calls the specific method in your class decorated with @Get('all').
  4. The Service is called by the controller to get the data.
  5. The Response is sent back through the controller, then the server, then to the client.

2. Defining the Route (The "Where")

To create a route, you use two decorators: one for the class and one for the method.

The Class Decorator: @Controller('cats')
This sets the "prefix". Every route inside this class will start with /cats.

The Method Decorator: @Get('all')
This defines the specific endpoint. Combined with the prefix, this creates the route: /cats/all.


@Controller('cats')
export class CatsController {
  @Get('all') // Route: GET /cats/all
  findAll() {
    return 'This action returns all cats';
  }
}

3. Capturing Data (The "What")

Most requests aren't static. You need data from the user. Nest provides "Param Decorators" to pluck data out of the request effortlessly.

1. Path Parameters (@Param)

Use this for required values that identify a specific resource (e.g., an ID).

Route: /cats/:id → User hits /cats/123


@Get(':id')
findOne(@Param('id') id: string) {
  return `This action returns cat #${id}`;
}

2. Query Parameters (@Query)

Use this for optional values like filtering, sorting, or searching.

Route: /cats → User hits /cats?breed=siamese


@Get()
findCats(@Query('breed') breed: string) {
  return `Searching for cats of breed: ${breed}`;
}

4. The Response: What happens when you return?

In some frameworks, you have to manually send a response: res.status(200).send(data). Nest simplifies this.

  • Returning an Object/Array → Nest automatically converts it to JSON and sets the status to 200 OK.
  • Returning a String → Nest sends it as text/plain with status 200 OK.
  • Returning nothing → Nest sends an empty response with status 200 OK.
Pro Tip: If you need to change the status code (e.g., return a 201 Created), you can use the @HttpCode(201) decorator on the method.
