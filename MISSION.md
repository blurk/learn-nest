# Mission: Backend Web Development with NestJS

## Why
User is targeting a **junior backend developer** role and has chosen NestJS as the framework to learn. Zero prior NestJS or Node/Express experience. Theory-first learning preference. Goal: build the conceptual foundation needed to ship production NestJS services confidently, not just pass tutorials.

## Success looks like
- Articulate the Nest mental model (modules, providers, DI, IoC) without code references
- Read an unfamiliar Nest codebase and predict where business logic lives
- Make defensible architectural decisions: feature module boundaries, provider scope, global vs encapsulated
- Pass a junior NestJS interview: "explain what `@Module()` does", "why is this provider request-scoped", "how does Nest resolve dependencies"
- Ship a small CRUD service end-to-end (controller → service → DB) on their own

## Constraints
- **Junior level**: assume no Node.js, no TypeScript, no backend HTTP knowledge beyond browser basics
- **Theory-first**: concepts and mental models before code; code only as illustration of theory
- **Zero prior Nest/Node/Express**: every term introduced fresh
- Lessons must build in storage strength (retrieval practice, not just reading)

## Out of scope (for now)
- Microservices, GraphQL, WebSockets (later, after REST + DB foundation)
- Deployment, Docker, CI/CD
- TypeORM/Prisma deep-dives (one database concept lesson later, not now)
- Authentication, authorization (separate learning track)
- Performance tuning, caching

## Learning philosophy applied
- Each lesson: one tightly-scoped concept, theory-first
- Quiz at end of each lesson to build storage strength (not fluency)
- Reference docs accumulate glossary + diagrams for later review
- Lessons link forward/back via anchors; lessons link to official docs as primary source
